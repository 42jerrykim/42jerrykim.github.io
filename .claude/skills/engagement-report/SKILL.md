# 성과 수집·분석 루프 (Engagement Report)

이 스킬은 [`post-quality-loop`](../post-quality-loop/SKILL.md)(내적 품질 루프)와 짝을 이루는 **외적 반응 루프**다. 품질 루프가 "루브릭이 정의한 좋은 글"로 수렴시킨다면, 이 루프는 "사람들이 실제로 찾고 읽는 글"이 무엇인지 측정해 (1) 기존 글의 개선 후보와 (2) 새 글의 주제 후보를 만들고, (3) 루브릭 자체가 독자 반응과 맞는지 분기마다 검증한다.

> **관계**: 상태 파일은 [`engagement.md`](../../quality/engagement.md)(성과판)와 [`topic-backlog.md`](../../quality/topic-backlog.md)(주제 백로그)다. 표·컬럼 정의는 각 파일 상단이 정본이다. 품질 점수는 [`scoreboard.md`](../../quality/scoreboard.md)에 있고, 이 스킬은 그것을 **읽기만** 한다.

## 두 축의 분리 원칙 (Goodhart 방지)

인기 지표를 품질 점수에 섞거나 품질 루프의 목표로 삼지 않는다. 트래픽을 직접 최적화 목표로 만들면 과장 제목·패딩으로 흐른다 — 측정이 목표가 되는 순간 측정이 망가진다. 따라서:

- 품질(루브릭)은 **게시 가능한가**를, 반응(성과판)은 **무엇을 쓰고 무엇을 고칠까**를 결정한다. 역할을 바꾸지 않는다.
- 제목·description 개선은 **본문이 실제로 답하는 내용을 검색 의도에 정확히 맞추는 것**이지, 클릭을 위한 과장이 아니다.
- 루브릭 개정은 이 스킬이 하지 않는다 — 분기 회고에서 **근거를 갖춘 제안**만 만들고, 개정은 사람이 결정한다.

## 데이터 소스와 접근 방법

| 소스 | 지표 | 접근 방법 | 상태 |
|------|------|-----------|------|
| Google Search Console | 페이지·검색어별 노출/클릭/CTR/순위 | ① Search Console API(서비스 계정) ② 폴백: Chrome 확장으로 UI 읽기 | 사이트 등록 완료, API 미연결 |
| GA4 (속성 `378371944`) | 페이지별 조회수·평균 참여 시간·유입 경로 | ① Data API `runReport`(서비스 계정) ② 폴백: Chrome 확장으로 UI 읽기 | 태그 2026-08-04 배포, API 미연결 |
| utterances | 글별 댓글 수·리액션 | `gh api` (아래 명령) — 자율 실행에서도 동작 | 동작 확인 완료 |

```bash
gh api --paginate "repos/42jerrykim/42jerrykim.github.io/issues?state=all&per_page=100" --jq '[.[] | select(.user.login == "utterances-bot") | {title, comments, reactions: .reactions.total_count, url: .html_url}] | sort_by(-.comments)'
```

### API 연결 사전 준비 (사람이 1회 수행)

야간 자율 실행에서 GSC·GA4를 수집하려면 브라우저 없이 호출 가능한 API 자격이 필요하다. 없으면 해당 소스는 건너뛰고 수집 이력에 "미수집" 사유를 남긴다(실패가 아니다).

1. GCP 프로젝트에서 **Google Analytics Data API**와 **Search Console API**를 활성화한다.
2. 서비스 계정을 만들고 JSON 키를 발급받아 저장소 **밖**(예: `%USERPROFILE%\.config\gcp\blog-metrics.json`)에 둔다. 키를 저장소에 커밋하지 않는다.
3. GA4 속성 `378371944`에 서비스 계정 이메일을 **뷰어**로 추가하고, Search Console 속성에도 **제한된 권한** 사용자로 추가한다.
4. 연결 후 첫 실행에서 API 조회가 UI에서 본 수치와 일치하는지 1회 대조한다.

## Stage 1 — 수집

1. 오늘 날짜를 터미널로 확인한다(`Get-Date -Format "yyyy-MM-dd"`).
2. utterances를 `gh api`로 수집한다.
3. GSC·GA4를 API(있으면) 또는 Chrome 확장(대화형 세션일 때)으로 수집한다. 기본 기간: GSC 최근 3개월, GA4 최근 28일. 페이지·검색어 각각 클릭수 상위 10개면 충분하다 — 전량 덤프는 하지 않는다.

## Stage 2 — 기록

[`engagement.md`](../../quality/engagement.md)의 각 표를 최신 스냅샷으로 **교체**하고, 수집 이력에 한 줄을 추가한다(과거와의 비교는 git 이력이 담당). 사이트 전체 합계(클릭/노출/CTR/평균 순위)는 수집 이력의 비고에 적는다.

## Stage 3 — 분석·백로그 갱신

수집한 스냅샷에서 다음 패턴을 찾아 [`topic-backlog.md`](../../quality/topic-backlog.md)에 `후보` 상태로 추가한다(이미 있는 항목은 근거 수치만 갱신). 모든 항목에 근거 데이터를 적는다 — 근거 없는 후보는 만들지 않는다.

- **저CTR 글**: 노출 상위인데 CTR이 사이트 평균에 크게 못 미치는 글 → `기존 글 개선`(제목·description 재작성) 후보. URL은 바꾸지 않는다 — 유입이 끊긴다.
- **미커버 주제**: 유입 검색어 중 대응하는 전용 글이 없거나 개론 글 하나가 여러 검색 의도를 받고 있는 것 → `신규 글` 후보.
- **강세 주제의 인접**: 클릭 상위 글의 인접·심화 주제 → `신규 글` 후보.
- **하락 신호**: 직전 스냅샷 대비 클릭이 뚜렷이 꺾인 글이 있으면 원인(순위 하락/계절성/경쟁 글)을 비고에 기록한다.

백로그의 `후보` → `승인` 전환은 사람만 한다. `승인`된 항목은 [`blog-agent-pipeline`](../blog-agent-pipeline/SKILL.md)으로 작성하고, 초안은 [`post-quality-loop`](../post-quality-loop/SKILL.md) 게이트를 통과시킨다.

## 분기 회고 — 루브릭 검증 (3개월마다)

스냅샷이 12주 이상 쌓이면 수행한다. [`scoreboard.md`](../../quality/scoreboard.md)의 루브릭 점수와 성과판의 반응 지표를 대조해 다음 질문에 답하는 짧은 보고서를 만든다.

- 루브릭 고득점 글이 실제로 더 읽히는가? 고품질·저반응 글과 저품질·고반응 글의 공통 패턴은 무엇인가?
- 반응을 예측하는 요소 중 루브릭이 측정하지 않는 것이 있는가(예: 검색 의도 부합, 제목의 명확성)?
- 그 결과 루브릭·작성 스킬에 어떤 개정을 제안하는가? — **제안까지만**. 개정 여부와 버전 올림은 사람이 [`rubric.md`](../post-quality-loop/rubric.md) 개정 절차로 결정한다.

## 드라이버 / 실행 방법

- **수동**: "성과 수집해줘" — 이 스킬을 호출한다. 대화형 세션이면 API 미연결 소스도 Chrome 폴백으로 수집할 수 있다.
- **정기(자율)**: 사용자가 `/schedule`로 등록한다(과금 자율 실행이므로 등록은 사람이 한다). 등록 문안 예시 — **주간**: "매주 월요일: engagement-report 스킬로 성과를 수집해 engagement.md를 갱신하고, topic-backlog.md에 근거 있는 후보를 추가하고, 요약을 보고한다. draft·rubric은 절대 바꾸지 않는다." / **분기**: "1/4/7/10월 첫 월요일: engagement-report의 분기 회고를 수행해 루브릭 개정 제안 보고서를 만든다. rubric.md는 수정하지 않는다."
- `/loop`(세션 내 반복)는 이 스킬에 필요 없다 — 수집은 1회성 작업이고 반복 주기는 주 단위다.

## 안전 원칙

1. 이 스킬은 콘텐츠·루브릭·스코어보드를 수정하지 않는다. 쓰는 파일은 `engagement.md`·`topic-backlog.md` 둘뿐이다.
2. `draft` 전환, `후보` → `승인` 전환, 루브릭 개정은 사람만 한다.
3. API 자격 증명은 저장소에 커밋하지 않는다.
4. 수집 실패는 건너뛰고 사유를 기록한다 — 부분 데이터로도 스냅샷은 유효하다.
