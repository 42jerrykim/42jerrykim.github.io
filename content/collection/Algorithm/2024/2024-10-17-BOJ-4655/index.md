카드를 이용하여 테이블 위로 얼마나 멀리 오버행을 만들 수 있는지에 대한 문제는 흥미로운 수학적 개념과 구현 능력을 요구한다. 이 문제는 주어진 카드의 수를 통해 최대한의 오버행을 달성하는 방법을 탐구하며, 이를 통해 조화수열의 성질을 활용한 효율적인 알고리즘을 구현할 수 있다.

문제 : [https://www.acmicpc.net/problem/4655](https://www.acmicpc.net/problem/4655)

## 문제 설명

카드를 쌓아 테이블 위로 얼마나 멀리 오버행을 만들 수 있는지 계산하는 문제이다. 카드가 한 장 있을 때, 최대 오버행 길이는 카드 길이의 절반이다. 두 장의 카드를 사용하면, 위쪽 카드가 아래쪽 카드 위로 카드 길이의 절반만큼 오버행하고, 아래쪽 카드는 테이블 위로 카드 길이의 1/3만큼 오버행하여 총 오버행 길이는 1/2 + 1/3 = 5/6 카드 길이가 된다. 일반적으로 n장의 카드를 사용할 때, 최대 오버행 길이는 1/2 + 1/3 + 1/4 + ... + 1/(n + 1) 카드 길이가 된다. 주어진 오버행 길이 c를 만족하거나 초과하기 위해 필요한 최소 카드의 수를 구하는 것이 목표이다.

입력은 여러 개의 테스트 케이스로 구성되며, 각 테스트 케이스는 0.00으로 끝난다. 각 테스트 케이스는 세 자리의 소수로 표현된 양의 부동 소수점 수 c가 주어진다. 출력은 각 테스트 케이스에 대해 최소 카드 수를 "X card(s)" 형식으로 출력한다.

## 접근 방식

이 문제를 해결하기 위해, n장의 카드로 만들 수 있는 최대 오버행 길이가 조화수열의 합으로 표현된다는 점을 이용한다. 조화수열은 무한히 증가하지만 느리게 증가하기 때문에, 원하는 오버행 길이 c에 도달하기 위해 필요한 최소 카드 수를 구하는 것은 반복적으로 조화수열의 항을 더해가는 방식으로 접근할 수 있다.

구체적인 접근은 단순하다. 오버행 길이를 0.0, 카드 수 n을 0으로 두고, 오버행이 c에 도달할 때까지 n을 1씩 늘리면서 1/(n + 1)을 더한다. 오버행이 c 이상이 되는 순간의 n이 필요한 최소 카드 수이며, 이를 "n card(s)" 형식으로 출력한다.

이 문제는 최대 오버행을 1/2 + 1/3 + ... + 1/(n+1) = H<sub>n+1</sub> − 1(H는 조화수)로 정의하므로, 풀이는 이 합을 c 이상이 되는 첫 n까지 누적하는 것으로 귀결된다. 같은 계열의 책 쌓기(book stacking) 문제는 Concrete Mathematics에서 다루며, 쌓는 단위 길이를 어떻게 정하느냐에 따라 계수가 1/2배로 바뀔 수 있으니 문제의 정의를 그대로 따라야 한다.

조화수 H<sub>m</sub>은 ln m + 0.5772(오일러–마스케로니 상수)에 근사하므로, 필요한 카드 수는 c가 커질수록 e<sup>c + 1 − 0.5772</sup> − 1 정도로 지수적으로 커진다. 반대로 말해 n이 작게 유지되므로 단순 누적 루프로 충분하다. 입력 c의 상한은 5.20이고 이때 답은 276장이다.

| c | 필요한 카드 수 n |
|---:|---:|
| 0.01 | 1 |
| 1.00 | 3 |
| 2.00 | 10 |
| 3.00 | 30 |
| 4.00 | 82 |
| 5.20 | 276 |

| 방법 | 테스트케이스당 시간 | 비고 |
|---|---|---|
| 누적 루프(본문 풀이) | O(n), n ≤ 276 | 구현이 가장 단순 |
| 누적합 선계산 + 이분탐색 | O(log n) | 테스트케이스가 매우 많을 때만 이득 |

이 방법은 간단하면서도 문제의 요구사항을 정확히 만족시킨다.

## C++ 코드와 설명

앞의 접근 방식을 그대로 옮긴 구현이다. 입력은 소수 셋째 자리까지의 실수이므로 `double`로 받고, 합산 루프가 곧 조화수의 부분합 계산이 된다.

```cpp
#include <bits/stdc++.h>
using namespace std;

int main(){
    double c;
    while(cin >> c){
        if(c == 0.00) break; // 입력이 0.00이면 종료
        double overhang = 0.0;
        int n = 0;
        while(overhang < c){
            n++;
            overhang += 1.0 / (n + 1); // 조화수열의 다음 항을 추가
        }
        printf("%d card(s)\n", n); // 결과 출력
    }
}
```

`while(cin >> c)`로 입력을 반복해서 받고 `0.00`이 들어오면 종료한다. 이어서 `overhang`을 0.0, 카드 수 `n`을 0으로 두고 `overhang < c`인 동안 `n`을 증가시키며 `1.0 / (n + 1)`을 더하므로, 루프를 빠져나온 시점의 `n`이 곧 답이다. 이를 형식에 맞춰 출력한다.

## Python 코드와 설명

같은 로직을 함수로 분리한 구현이다. 계산부를 `calculate_min_cards`로 빼 두어 입력 파싱과 분리했고, 빈 줄이 들어와도 `float('')` 예외가 나지 않도록 건너뛴다.

```python
def calculate_min_cards(c):
    overhang = 0.0
    n = 0
    while overhang < c:
        n += 1
        overhang += 1.0 / (n + 1) # 조화수열의 다음 항을 추가
    return n

def main():
    import sys
    for line in sys.stdin:
        c_str = line.strip()
        if not c_str:
            continue
        if c_str == "0.00":
            break
        c = float(c_str)
        cards = calculate_min_cards(c)
        print(f"{cards} card(s)")

if __name__ == "__main__":
    main()
```

`calculate_min_cards(c)`는 오버행 `c`를 받아 필요한 최소 카드 수를 돌려주고, `main()`은 표준 입력을 한 줄씩 읽어 `0.00`에서 멈춘다. 여러 테스트 케이스가 한 번에 들어와도 줄마다 독립적으로 계산해 출력한다.

## 코너 케이스 및 실수 포인트

| 케이스 | 설명 | 처리 방법 |
|---|---|---|
| **작은 c** | c = 0.01이어도 카드 1장(오버행 0.5)이 필요하다 | n을 0이 아닌 1부터 세는 구조(루프 안에서 먼저 증가) 유지 |
| **최댓값** | c = 5.20이면 n = 276 | 루프가 수백 회에 그치므로 int로 충분하며 오버플로우 걱정은 없다 |
| **부동소수점 경계** | c가 합과 거의 같을 때 `overhang < c` 비교 오차 | 입력이 소수 셋째 자리까지이므로 수천 번 이내 누적 오차는 1e-12 수준이라 실무상 안전하지만, 불안하면 `c - 1e-9` 와 비교 |
| **종료 조건** | 입력 `0.00`에서 종료 | 문자열 비교(Python) 또는 `c == 0.00`(C++) 모두 입력이 정확히 0일 때 동작 |
| **빈 줄(Python)** | `float('')` 예외 | 빈 줄은 건너뛰도록 `if not c_str: continue` 추가 |

## 이 글을 읽은 후 달성해야 할 목표

- 카드 쌓기 오버행이 조화수의 부분합 H<sub>n+1</sub> − 1로 표현되는 이유를 설명할 수 있다.
- H<sub>m</sub> ≈ ln m + γ 근사로 입력 상한에서의 답 크기를 추정하고, 단순 루프와 선계산 방식 중 무엇을 쓸지 판단할 수 있다.
- 부동소수점 누적 비교에서 경계 오차가 생기는 조건을 설명할 수 있다.
